# Spec: wikipedia-demand-signals

Статус: **чернетка на рев'ю** · 2026-09-24 · дедлайн кейсу 2026-09-27 23:59

## 1. Мета

Навичка (Agent Skill) для AI-агента, з якою засновники B2C-продуктів оцінюють інтерес до тем у різних мовних розділах Wikipedia: чи зростає інтерес, де він сильніший, наскільки велика аудиторія і наскільки цьому можна довіряти. Результат: коротка відповідь у чаті, графік і PDF на одну сторінку.

**Головний принцип:** усі обчислення й висновки робить код, а агент лише розуміє запит, викликає команду й переказує готовий результат. Тому навичка має надійно працювати на Claude Haiku 4.5.

**Користувацькі сценарії** (приклади з завдання + уточнення):
1. «Порівняй зростання інтересу до інтервального голодування в pl і cs за останні два роки».
2. «Чи зростає інтерес до астрономії в uk-Вікіпедії і наскільки цьому можна довіряти?»
3. «Порівняй інтерес до вивчення англійської в обраних розділах і підготуй звіт: які аудиторії досліджувати далі?»
4. Уточнення після першої відповіді: «додай словацьку», «тепер важливіший розмір аудиторії», «зроби звіт українською».

## 2. Стек

- Python ≥ 3.11. Залежності вказані в заголовку скрипта (PEP 723): `numpy`, `matplotlib`. Більше нічого, HTTP через стандартну бібліотеку.
- Запуск через `uv run` (uv ставить залежності сам, `.venv` у репозиторії не створюється). Без uv: `requirements.txt` із зафіксованими версіями.
- Тести: `pytest`; `scipy` потрібен тільки в тестах, щоб звірити нашу реалізацію Mann-Kendall / Theil-Sen.
- Графіки та PDF: matplotlib (`PdfPages`, шрифт DejaVu Sans, який підтримує кирилицю, `ł`, `ř`, `ě`).

## 3. Команди

```bash
# основні (запускаються з кореня навички; якщо uv немає в PATH, то `python -m uv run ...`)
uv run scripts/wds.py resolve "intermittent fasting" --langs pl,cs
uv run scripts/wds.py analyze --qid Q<id> --langs pl,cs --period 24m
uv run scripts/wds.py analyze --qid Q<id> --langs pl,cs,sk --period 24m --rank-by size --report --report-lang uk --note "..."

# без uv
python -m pip install -r requirements.txt && python scripts/wds.py ...

# тести, лінт, валідація формату
uv run --with-requirements requirements-dev.txt pytest tests/
uvx ruff check scripts tests
python <skill-creator>/scripts/quick_validate.py .
```

### Контракт CLI

**`resolve <запит> --langs <коди|назви>`** повертає до 5 кандидатів:
`qid`, `label`, `description`, `sitelinks` (назва статті для кожної мови або `null`), `found_via` (`wikidata` | `fulltext`), а також прапорець `ambiguous`.
Спершу `wbsearchentities`; якщо порожньо, повнотекстовий пошук Wikipedia (`list=search`) → QID з `pageprops`.

**Неоднозначна vs широка тема.** Рішення, чи перепитувати, ухвалює код, а не модель:
- `ambiguous: true`, якщо найкращий кандидат — сторінка неоднозначності або кілька кандидатів мають близьку оцінку збігу («Меркурій», «Java»). Тоді агент ставить **одне** уточнювальне питання.
- Широка тема («астрономія») не є неоднозначною. Агент бере основну статтю, прямо називає це допущенням і пропонує додати пов'язані статті. Без питання.

**`analyze`** приймає:
- `--qid Q…` (можна кілька) або `--article <lang>:<Title>` для статей без Wikidata;
- `--langs pl,cs` (ISO-коди або англійські назви; `nb` → `no.wikipedia` тощо);
- `--period 12m|24m|36m|5y` (за замовчуванням `24m`) або `--from YYYY-MM --to YYYY-MM`. Дати рахує скрипт, а не агент;
- `--rank-by growth|share|size` (за замовчуванням `growth`);
- `--report` — PNG + PDF; `--report-lang en|uk`; `--note "<рекомендація агента>"` — **без цифр** (якщо є цифра, помилка з поясненням); `--out <dir>` (за замовчуванням `./wds-output/`).

**Вивід у stdout:** компактний JSON (UTF-8, `ensure_ascii=False`), приблизно 20–40 рядків, числа округлені:
```json
{
  "status": "ok",
  "period": {"from": "2024-09", "to": "2026-08", "months": 24},
  "results": [
    {"qid": "Q<id>", "lang": "pl", "title": "Post przerywany",
     "views_last_12m": 184210, "views_prev_12m": 151003, "growth_pct": 22.0,
     "per_million_last_12m": 41.3, "per_million_growth_pct": 29.5,
     "trend": "rising", "confidence": "medium",
     "reasons": ["…"], "warnings": ["…"]}
  ],
  "ranking": {"by": "growth", "order": ["pl", "cs"]},
  "caveats": ["language edition ≠ country", "interest ≠ willingness to pay", "…"],
  "files": {"data_csv": "…", "chart_png": "…", "report_pdf": "…"}
}
```
Помилки мають вигляд `{"status": "error", "error": "...", "hint": "..."}` і пишуться для агента: «unknown language 'polski', did you mean 'pl'?». Прогрес пишеться в stderr. Повні часові ряди йдуть у CSV, не в stdout.

## 4. Дані й метрики

**Завантаження**
- Pageviews API, `agent=user`, `all-access`, **щоденні** дані для статті та для всього розділу (`aggregate`), за період + 12 місяців до нього (база для «рік до року»). Місяці агрегуємо самі.
- До 10 редиректів статті (MediaWiki `prop=redirects`, простір імен 0) додаються до ряду. Якщо редиректів більше, пишемо попередження.
- Назви кодуються в коді (`urllib.parse.quote`, UTF-8). 404 для знайденої статті означає нулі.
- Запити йдуть послідовно, приблизно 3/с. На 429/503 чекаємо `Retry-After` (якщо заголовка немає, то ≥5 с з експоненційною затримкою, максимум 5 спроб).
- `User-Agent: wikipedia-demand-signals/<версія> (+<URL репозиторію>)`, можна перевизначити через `WDS_USER_AGENT`. Email не вказуємо.
- Кеш: `%LOCALAPPDATA%/wikipedia-demand-signals` або `~/.cache/…`. Кожна відповідь записується одразу, тож повторний запуск після таймауту продовжує з місця зупинки. Завершені дні зберігаються назавжди, пошук і редиректи — 7 днів.

**Очищення рядів**
- Пропущені дні заповнюються нулями, але тільки після дати створення статті (перша правка). Ряд до створення обрізається, з попередженням.
- Неповний поточний місяць відкидається.
- Різка стійка зміна рівня (≥3× між медіанами сусідніх вікон) дає попередження: «можливе перейменування або зміна в усьому розділі».

**Метрики (на кожну статтю × мову)**
- `views_last_12m`, `views_prev_12m`, `growth_pct` — розмір аудиторії та зростання «рік до року» (прибирає сезонність).
- `per_million_*` — частка від усіх переглядів розділу. Прибирає ефект розміру розділу та загальні зміни трафіку Wikipedia.
- Тренд: Theil-Sen (нахил) + Mann-Kendall (стійкість) по **місячному** нормалізованому ряду; реалізація на numpy.
- Сплески: частка переглядів періоду за 5 найактивніших днів.
- Обсяг: медіана переглядів за місяць; якщо дуже мала, ряд вважається шумним.

**Вердикт:** `trend` ∈ {rising, flat, falling}, `confidence` ∈ {high, medium, low} за явними правилами з порогами, а не зваженим балом. Орієнтир:
- **high** — Mann-Kendall значущий, знак збігається з «рік до року» для сирих і нормалізованих переглядів, немає сплесків і попереджень, обсяг достатній, ≥ 24 місяців даних;
- **medium** — напрям узгоджений, але одна умова не виконана;
- **low** — решта випадків або малий обсяг / зміна рівня / < 12 місяців даних.
Пороги — іменовані константи з обґрунтуванням у коді й `references/methodology.md`, підібрані на синтетичних рядах. p-value користувачу не показуємо. Кожне правило, що спрацювало, додає рядок у `reasons`.

**Звіт (`--report`)**
- PNG: помісячні перегляди на мільйон та абсолютні перегляди по мовах.
- PDF A4, 1 сторінка: заголовок і параметри, таблиця метрик, графік, вердикти з причинами, `note` агента, незмінні застереження, джерела й дата.
- Усі цифри та тексти в PDF беруться з шаблону (en/uk), а агент дає лише `note`.

## 5. Структура проєкту

Корінь репозиторію = директорія навички (назва папки = `name` у SKILL.md).
```
wikipedia-demand-signals/
  SKILL.md                 ← для агента (EN): коли використовувати, робочий процес, 2 команди, як читати JSON, що обов'язково сказати
  README.md                ← для людей (UK): логіка, рішення, обмеження, як перевіряли, план розвитку
  requirements.txt / requirements-dev.txt
  scripts/
    wds.py                 ← CLI (PEP 723 заголовок), тільки парсинг аргументів і вивід
    wds_lib/               ← api.py (HTTP, кеш, ліміти), resolve.py, langs.py, series.py (очищення),
                              stats.py (MK, Theil-Sen), verdict.py, report.py, i18n.py
  references/methodology.md ← метрики й пороги (UK), агент читає лише на питання «чому»
  evals/evals.json + evals/results/  ← запити, критерії, підсумки прогонів на Haiku
  tests/                   ← pytest + fixtures (записані відповіді API)
  docs/SPEC.md, docs/plan.md, docs/todo.md
```
Мова: усе, що читає агент (SKILL.md, JSON, помилки), англійською; документи для людей українською.

## 6. Стиль коду

Невеликі чисті функції, type hints, без класів там, де вистачає функцій. Константи мають імена й пояснення, «магічних чисел» немає.
```python
# A topic with fewer than ~300 views/month moves by tens of percent from noise alone;
# growth on such a base is reported but never above "low" confidence.
MIN_MEDIAN_MONTHLY_VIEWS = 300

def growth_pct(last: float, prev: float) -> float | None:
    """Year-over-year change in percent; None when the base is zero."""
    return None if prev == 0 else round((last - prev) / prev * 100, 1)
```
`ruff` із налаштуваннями за замовчуванням.

## 7. Тестування

1. **Юніт-тести на синтетичних рядах із відомою відповіддю:** рівний ряд + один сплеск → не «rising», low; лінійне зростання з шумом → rising; чиста сезонність → flat; стрибок рівня → попередження; коротка історія → low; малий обсяг → low.
2. **Статистика:** Mann-Kendall / Theil-Sen звіряються з `scipy` на випадкових рядах.
3. **Очищення даних:** заповнення нулями, відкидання неповного місяця, обрізання за датою створення, мапінг мов, валідація `--note`.
4. **Інтеграційні тести без мережі:** записані відповіді API в `tests/fixtures/`. Один живий smoke-тест позначений окремо.
5. **Ручна звірка** 2–3 статей із pageviews.wmcloud.org, результат записується в README.
6. **Evals на Haiku** (через `skill-creator`, коли пишемо SKILL.md): ≥ 5 запитів — 3 з завдання, уточнення «додай мову / зміни критерій», неоднозначна тема або мова без статті. Для кожного запиту два прогони, із навичкою і без неї (база для порівняння), на субагентах Haiku. Критерії: викликав resolve → analyze; кожне число у відповіді є в JSON; назвав рівень довіри й застереження; перепитав за неоднозначності; PDF є, коли просили. Плюс один ручний прогін `claude --model haiku` у чистій папці, куди навичка підключена через junction у `.claude/skills/`.

## 9. Критерії готовності

1. Три приклади з завдання проходять повністю на Haiku 4.5 у чистій папці: правильні команди, числа у відповіді збігаються з JSON, названі довіра й застереження, PDF на 1 сторінку є, коли просили.
2. Уточнення «додай sk» дозавантажує лише нові дані (видно в stderr), повторний запуск < 5 с.
3. Перший запуск для 3 мов × 2 статей < 90 с (запас до 2-хвилинного таймауту Bash).
4. Усі синтетичні сценарії з розд. 7 дають очікуваний вердикт; MK/Theil-Sen збігаються зі scipy.
5. Числа для 2–3 статей збігаються з pageviews.wmcloud.org.
6. Назви pl/cs/uk коректні в stdout на Windows і в PDF.
7. Фронтматер проходить валідацію; `description` ≤ 1024 символів; `SKILL.md` ≲ 150 рядків.
8. У README є порівняння «з навичкою / без навички» на Haiku, обмеження та план розвитку.
9. Перевірка анонімності: пошук імені/email у репозиторії та `git log` нічого не знаходить.

## 11. Ухвалені рішення (з відкритих питань)

1. Тема = одна основна стаття за замовчуванням; агент може передати кілька QID, якщо тема їх охоплює. Перепитує лише при `ambiguous: true` (див. розд. 3).
2. Мова звіту: `en` за замовчуванням; `uk`, якщо користувач пише українською.
3. Приватний репозиторій на GitHub створюється одразу (історія комітів видна після публікації); його URL іде в User-Agent.
