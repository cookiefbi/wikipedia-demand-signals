# План реалізації

Джерело вимог: [SPEC.md](SPEC.md). Задачі з критеріями: [todo.md](todo.md).

## Підхід

**Спершу наскрізний шлях, потім якість.** До кінця 25.09 проходить весь ланцюжок запит → `resolve` → `analyze` → графік → PDF → SKILL.md → прогін на Haiku, хай навіть із простими метриками. Головний ризик — як дешева модель користується інтерфейсом навички, тож перевіряємо це першим. Складніша статистика (P1) додається всередину модулів і не змінює контракт CLI.

## Компоненти і залежності

```
langs ─┐
api ───┼─> resolve ──────────────┐
       └─> pageviews ─> series ──┼─> verdict ─> report
                         stats ──┘      │
                                        └─> wds.py (CLI) <── SKILL.md
```

| Модуль (`scripts/wds_lib/`) | Відповідальність |
|---|---|
| `langs.py` | коди/англійські назви мов → проєкт Wikipedia (`nb` → `no`), підказки для помилок |
| `api.py` | HTTP GET: User-Agent, ~3 запити/с, повтори на 429/503 з `Retry-After`, файловий кеш із TTL |
| `resolve.py` | обидва пошуки, `wbgetentities`, фільтр сторінок неоднозначності, сортування, `ambiguous` |
| `pageviews.py` | фіксоване 72-місячне вікно, щоденні дані статті й розділу, редиректи (P1), дата створення (P1) |
| `series.py` | заповнення нулями, обрізання, помісячна агрегація, відкидання неповного місяця |
| `stats.py` | Mann-Kendall, Theil-Sen на numpy (P1) |
| `verdict.py` | метрики, `trend`, `confidence`, `topic_totals`, ранжування, `assumptions`, застереження |
| `report.py` + `i18n.py` | PNG і одна сторінка PDF (matplotlib), шаблони en/uk |
| `scripts/wds.py` | CLI: аргументи, UTF-8 stdout, JSON + `result.json`, формат помилок |

## Порядок і контрольні точки

1. **Каркас + `api` + `langs`**: основа, яку можна протестувати без мережі.
2. **`resolve` на справжніх даних.** Записуємо відповіді API для 5 запитів і тестуємо на них правила.
   ✅ *Контрольна точка A:* `resolve` видає очікуване для astronomy / intermittent fasting / learning English / Java / Mercury.
3. **`pageviews` + `series` + простий `verdict` → `analyze`.**
4. **`report`** (можна паралельно з кроком 3 на синтетичних рядах) + звірка з pageviews.wmcloud.org і прогін у PowerShell.
   ✅ *Контрольна точка B:* `analyze --report` з папки користувача дає JSON, CSV, PNG і PDF на 1 сторінку, pl/cs/uk без «кракозябр».
5. **SKILL.md через `skill-creator` + тестова папка для Haiku** (junction, `.claude/settings.json`, пробіл у шляху).
   ✅ *Контрольна точка C (кінець P0):* 3 приклади із завдання на Haiku. Записуємо, де модель спіткнулася, і це стає першою задачею P1.
6. **P1:** редиректи, дата створення, MK/Theil-Sen, сплески, повні правила довіри, `topic_totals` + `--rank-by`, `--note`, uk, зміна рівня.
   ✅ *Контрольна точка D:* усі синтетичні сценарії дають очікуваний вердикт; MK/Theil-Sen збігаються зі scipy.
7. **P2:** evals із навичкою і без неї, `check_numbers.py`, methodology, README, анонімність, публікація.

## Ризики

| Ризик | Що робимо |
|---|---|
| Haiku неправильно користується CLI | прогін уже в P0; помилки з підказками; короткий SKILL.md із прикладами |
| Ліміти Wikimedia / таймаут Bash | послідовні запити, кеш кожної відповіді, фіксоване вікно, ліміт 10 мов, оцінка часу в stderr |
| Кодування на Windows | `reconfigure(utf-8)`, `ensure_ascii=False`, `result.json`, тест із pl/cs/uk-назвами |
| PDF вилазить за 1 сторінку | фіксований розмір A4, обрізання довгих списків, тест на кількість сторінок |
| Не встигаємо в P1 | порядок відмови зі SPEC розд. 10; те, що впливає на вердикт, не відкидається |
| Правила придумані на уявних даних | фікстури зі справжніх відповідей API (уже знайдено 3 контрприклади) |
